# 0.3.1 — 2026-11-23

## Added

- **`unesco_search_biosphere_reserves` filters by periodic review** ([#28](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/28)): `reviewed_from` / `reviewed_to` bound the year of a reserve's latest review, and `reviewed` keeps reserves with or without a recorded review. Rows carry `last_periodic_review_year`. `reviewed: false` with a bound fails as the new `review_filter_conflict`, checked before the review range, and `invalid_year_range` also covers the review bounds.
- **`unesco_search_sites` rows carry `components_total`** ([#27](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/27)), and the facts line states a serial site's coordinates as per component instead of `Not available`.

## Changed

- **`limit` and `max_components` are served as requested, up to 10,000** ([#26](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/26)): every search tool was cut to 50 rows and `unesco_get_site` to 1,000 components. 10,001 is still rejected; cursors are unaffected.
- **Maintenance**: framework skills, scripts, and templates synced to `@cyanheads/mcp-ts-core` 0.13.22. An installed server resolves its app root to its own package when launched from another project's root, an argument rejection for a stringified number outside a bound names that bound, and `engines.bun` rises to `>=1.4.4`.

## Fixed

- **`whc001`, `mab001`, and `eg0001` load again** ([#30](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/30)): the Data Hub now exports their text booleans lowercase (`true`/`false`) and the strict row schemas rejected every row, so every site, biosphere reserve, and geopark tool answered `snapshot_unavailable`. The five fields are read in any case; any other value still fails the row.
- **`ich001` descriptions lose the ICH site's page markup** ([#29](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/29)) in English and French at load.
- **`unesco_get_intangible_heritage_element` renders the image caption as a labelled blockquote** ([#24](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/24)) in `content[]`, with blank lines keeping the credits outside it, so a long or multi-line caption round-trips.
- **`periodic_review_years` no longer lists a follow-up report year that UNESCO marks `FU`** ([#28](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/28)); 0.3.0 served it as a review.
- **`whc001` descriptions in every language and statements of Outstanding Universal Value show `'` where the export doubles an apostrophe** (`L''viv` → `L'viv`); in a value that also holds a single apostrophe, `''` is a typed double quote and shows as `"`. Names, credits, and component names are unchanged.
- **`unesco_get_site` `content[]` states `**Components:** None listed`** for a site UNESCO lists no components for, matching `components_total: 0` in `structuredContent`.
- **The `.mcpb` bundle starts under Node again**: the 0.3.0 bundle cleaner removed SDK runtime modules.
