# 0.3.0 — 2026-11-04

## Added

- **`skill://unesco-heritage-guide/SKILL.md`** resource and the `skill://{+path}` resource template: the server publishes `skills/unesco-heritage-guide/SKILL.md` (landmark lookups, empty results, `near` chains, partial answers) through `createApp({ skills: 'skills' })`. The server instructions point to it, and `skills/` ships in the npm package, the Docker image, and the `.mcpb` bundle.
- **`component` keyword tier** in `unesco_search_sites` ([#21](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/21)): `query` words also match component names, ranked between `name` and `description`, and `matched_in` gains `component`. When a query word matches a component name and none of the site's own names, the row lists up to 10 `matched_components` (`ref`, `name`, `latitude`, `longitude`) with `matched_components_total`.

## Changed

- **`unesco_list_reference` `countries`, `regions`, and `datasets` answer from the datasets that loaded** ([#22](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/22)). An unavailable dataset's counts are absent (rendered `Not available`, never `0`), its `datasets` row reports `available: false` and `retryable` without `records`, `data_as_of`, `license`, or `coverage_notes`, `sources` lists the loaded datasets, and `notice` names each unavailable one ahead of any filter fragment. The call still fails with `snapshot_unavailable` when none of the topic's datasets loads.
- **Maintenance**: framework skills (new `add-skill`) and scripts synced to `@cyanheads/mcp-ts-core` 0.13.18, including the bundle agent-doc fix (cyanheads/mcp-ts-core#794) with `tests/scripts/bundle-agent-docs.test.ts`; root `plugin.json` and `mcp.json`; the Dockerfile creates and copies `skills/`; `bunfig.toml` `minimumReleaseAge` 259200 → 86400 seconds.

## Fixed

- **`whc001` loads again** ([#19](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/19)): `iso_codes` as a JSON array, `coordinates` as a GeoJSON `MultiPoint` Feature (a one-point MultiPoint is the site's `latitude`/`longitude`, a multi-point one gives none), and `components_list` as a JSON array (`null` or `"[]"` lists none). An entry with a missing or mistyped key, a blank `ref`, or an out-of-range coordinate is skipped and counted in `components_unparsed`; the previous shapes fail the row.
- **`ich001` loads again** ([#20](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/20)): a `world_heritage_sites` link takes its `id_no` from its `https://whc.unesco.org/en/list/{id}` `url`, since the export serves `ref` empty, and a link without that `url` fails the row. `main_image_caption_en` takes the 65,536-character bound.
- **A row schema failure surfaces once, with its `issues`** ([#23](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/23)): the row mapper no longer wraps it in a second "could not be mapped" error, and the refresh warning logs the issues.
