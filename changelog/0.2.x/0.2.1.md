# 0.2.1 — 2026-10-17

## Added

- **`description_language`** on `unesco_get_site` (`en`, `fr`, `es`, `ru`, `ar`, `zh`) and `unesco_get_intangible_heritage_element` (`en`, `fr`) returns UNESCO's description in that language, names it in the output's `description_language`, and labels it in `content[]` ([#16](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/16)). Where UNESCO publishes none, the English description comes back as `en` with a `notice`; the statement of Outstanding Universal Value and the resources stay English. The element tool gains an optional `notice` enrichment field.

## Changed

- **`limit` on the four searches and `max_components` on `unesco_get_site`** accept values up to 10,000 and serve them at the per-call cap (50 and 1000) instead of rejecting ([#15](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/15)). `cap`, `applied_filters.limit`, and a leading `notice` report the clamp; a value above 10,000 still rejects.
- **`snapshot_unavailable` contracts** (9 tools, 4 resources) cover a rejected or unusable export and no longer declare a static `retryable` ([#9](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/9)).
- **Maintenance**: Docker image on Bun 1.4.3 prunes musl-only packages from the production tree; CodeQL runs one job per language under `/language:<language>`; `server.json` npm entries launch through `npx` with `MCP_TRANSPORT_TYPE=http` on the HTTP entry; framework scripts and skills synced to `@cyanheads/mcp-ts-core` 0.13.15; `.env*` ignore rules; the fuzz suite drops the input's own escaped echo from its leak check (test-only, around cyanheads/mcp-ts-core#754).

## Fixed

- **A load failure the server cannot retry reports `retryable: false`** ([#9](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/9)): a Data Hub 4xx other than 408, 425, or 429, or data the server refuses (row schema, license, size, a missing required field), surfaces as `snapshot_unavailable` with no `retryAfter` and a recovery that does not say to wait. Network errors, timeouts, 5xx, and 429 keep `retryable: true` and `retryAfter`.
- **The export `select` is bounded by the dataset metadata's field list** ([#9](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/9)): image, `website`, and translation columns the metadata no longer lists load as absent with one warning log, and any other missing field fails the load before the export request, naming it.
- **`near` decides on unrounded distances** ([#10](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/10)): the radius match, the nearest point, and the `distance` sort use exact kilometres; `distance_km` shows 0.1 km rounding, never above `radius_km`, and `nearest_component` appears when a component is strictly nearer before rounding.
- **Upstream URLs decode HTML entities before parsing** ([#11](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/11)): `unesco_get_biosphere_reserve` and `unesco://biosphere-reserve/{mab_id}` return `website` values with `&amp;` as `&`, so query parameters keep their names.
- **A malformed `cursor` on the four searches returns the tool's declared `invalid_cursor` recovery** ([#12](https://github.com/cyanheads/unesco-heritage-mcp-server/issues/12)), which names `next_cursor`, whatever hint the framework decoder attaches (cyanheads/mcp-ts-core#603).
